# Windows npm Codex launch correction

The shell-free bridge previously launched `codex` directly on every platform. Windows npm installs a `codex.cmd` wrapper, which cannot be used as an executable by `execFile` without a command shell, as described in the official [Node child-process documentation](https://nodejs.org/download/release/v26.8.2/docs/api/child_process.html#spawning-bat-and-cmd-files-on-windows). Windows now retains its direct executable probe, then detects the fixed npm package layout beside a PATH command directory: `codex.cmd`, package name `@openai/codex`, and `bin/codex.js`. The bridge uses its own Node runtime and the canonical script path, preserving the existing agent arguments as separate literal arguments. It never passes prompts, checkout paths or repository instructions through `cmd.exe` or shell text.

Status and dispatch share the adapter. Unix dispatch keeps the original direct command behavior. An initial regression run caught an unnecessary help probe changing Unix dispatch fixtures; the correction confines the fallback to Windows. The final full run passes **195 Node + 159 Convex = 354 tests**. The new test launches a help-only fixed JavaScript fixture, checks exact literal metacharacter/prompt/checkout arguments, rejects unrelated package metadata, and proves Unix keeps its direct command. This is adapter/process evidence on macOS, not native Windows acceptance.

Typecheck, lint and local build pass. The existing native macOS status detects all three agents with exit 0. Current source is delivered to the isolated Linux guest; actual status detects all three agents and retains missing-pairing recovery with expected exit 1. No agent prompt, pairing, credential or inference occurred. Hosted frontend release remains unchanged; actual Windows installation, protocol launch, agent fix and recovery cases still require a Windows environment.

The installed local official Codex package supplies the verified fixed JavaScript entry layout. Current official [Cursor CLI installation](https://cursor.com/docs/cli/installation) also provides native Windows installation; its downloaded public PowerShell installer identifies architecture-specific packages and copies `cursor-agent` executables. No Windows installer was executed and no native Windows support is inferred from that source alone.

Artifacts in `output/setup/`: `windows-codex-adapter-{final-tests,final-types,lint,build}.log`, native status logs (macOS status retained privately), and the public Cursor Windows installer source. Current acceptance audit also records unchanged hosted GitHub resolution/budget, both typechecks and 12 offline fixture validations in `current-acceptance-*` receipts.
