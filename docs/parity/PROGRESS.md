## Decisions (date — decision — reason)
- 2026-10-14 — Grammar source: tree-sitter-wasms 0.1.13 on web-tree-sitter 0.22.6 (newest runtime that loads those builds) rather than 11 separate grammar packages — one pinned package covers every required language; revisit when a maintained multi-grammar build for the 0.25+ ABI exists.
- 2026-10-14 — Calls resolve at index time only via same-file definitions, named imports and imported qualifiers (no cross-file symbol table during per-file batches); Kotlin top-level functions and Go packages resolve to package directories that traversal expands.
- 2026-10-14 — Parser packages ship as Convex node externalPackages (installed, ~50 MB) and load through literal dynamic imports so the Convex bundler registers them.
- 2026-10-14 — Agentic resume uses a `waiting_agent` review status + per-review state blob (saved every turn) and a soft step deadline (AGENT_STEP_SECONDS=420) instead of a separate job table — reuses the existing review lifecycle, recovery sweep and retry semantics; resumes capped at 6.
- 2026-10-14 — Agent budgets count uncached input + output tokens (cache reads excluded) because every turn re-sends the cached review payload.
- 2026-10-14 — Agent tool results from the index are labelled with the indexed SHA; read_file always resolves to the PR head tree so cited evidence matches the reviewed revision.
- 2026-10-14 — Agentic CLI (`src/cli.ts`) support deferred; the engine is available to server reviews and `pnpm eval --engine=agentic`.
- 2026-10-14 — Review file limits per mode: fast 200, standard 350, deep 500 (was a hard failure above 500 for all modes); payload stays capped at 300 KB with lowest-risk trimming — keeps cost bounded while never failing outright.
- 2026-10-14 — Rules and learned preferences in repositories.data are capped at 1,000 rows each (newest preferences first) — bounded reads; real deployments are far below this.
- 2026-10-14 — `pnpm test:e2e` runs at the end of each phase rather than after every small dashboard change, since it needs both local dev servers.
- 2026-10-14 — Anthropic structured output uses `output_config.format` (GA, no beta header), not forced tool use — forced tool_choice conflicts with always-on adaptive thinking on Claude 5.x.
- 2026-10-14 — Specialists share one system prompt; the review payload moves to `ModelRequest.context` (a stable prefix) and the category goes in a small trailing `assignment` input — lets 7 specialist calls share one cache write instead of 7 full-price inputs. Repairs are appended after the prefix on Anthropic.
- 2026-10-14 — `runTools` is an optional `ModelProvider` member so existing fake providers compile; agentic callers must fall back when absent.
- 2026-10-14 — Haiku 5.5's >100k-token tier is chosen from the reservation ceiling (request bytes); settlement reuses the reserved price — may over-count budget for mid-size prompts, never under-count.
- 2026-10-14 — gpt-5.4/5.5 (context-tiered at 272k) are not built-in prices; operators can add them via INFERENCE_PRICES.
- 2026-10-14 — Display cost now falls back to the built-in price table when LLM_*_COST_PER_MILLION is 0 (previously reported 0).
- 2026-10-14 — Default output limit is 16000 for Claude/reasoning models because thinking tokens count toward max_tokens; 6000 otherwise (unchanged).
- 2026-10-14 — The baseline commit includes `.claude/skills/greptile-parity/` — the plan must travel with the repo so any agent can resume.

- 2026-10-14 — Memory scope is stored on the record (scope + teamId snapshot at edit time) and applied at read time through an (organizationId, scope) index — no copying of preferences into other repositories, so disable/delete takes effect everywhere at once.
- 2026-10-14 — Edited preferences reuse the convention guardrails but allow "do not flag X" wording outside security, because narrowing noise is what a preference is for; security-related suppression stays rejected.

- 2026-10-14 — `@openreview fix this` opens a pull request only when the comment asks for one ("in a new PR") and the repository setting allows it; a plain "fix this" never writes to the repository — least surprise for a command anyone with write access can type.
- 2026-10-14 — Fix pull requests are opened only for same-repository changes at the exact reviewed head, from a new `openreview/fix-<pr>-<fingerprint>` branch via the Contents API (preserves file mode, one commit) — forks are skipped because the app cannot write to them and opening against a fork branch from the base repository is not possible.

- 2026-10-14 — Chat streaming design: the Convex job persists progress events and the validated answer on the assistant message; a session-authenticated Next.js route (`/api/chat/[messageId]/stream`) polls `chat.progress` with ConvexHttpClient every 500 ms and relays Server-Sent Events. Chosen because model keys and the inference budget live only in Convex and sessions are custom JWTs (no Convex auth on the browser). Investigation steps stream live; answer text is released only after citation validation, so no unvalidated claim ever reaches the browser (token-level streaming would show unverified text).
- 2026-10-14 — Chat reads files only from the stored index at `indexedSha` (no provider API calls), so every citation is pinned to one revision per repository and chat works without SCM tokens; past findings and custom rules are not exposed to chat.
- 2026-10-14 — Chat messages order by insertion (`_creationTime`), not `createdAt`, so messages written in the same millisecond keep their order.

- 2026-10-14 — API key scopes are hierarchical (admin ⊃ write ⊃ read) and keys without a stored scope list keep full access, so existing integrations keep working; the key owner's role still bounds every call.
- 2026-10-14 — `POST /api/query` reuses codebase chat (threads owned by the key owner, tagged `origin: "api"`) instead of a separate engine — one validation path for citations, shared rate limits and inference budget.

- 2026-10-14 — Notion API calls pin `Notion-Version: 2022-06-28` (stable page/block shapes) rather than the SDK default 2025-09-03, which reworks databases into data sources that OpenReview does not need; revisit if Notion retires 2022-06-28.
- 2026-10-14 — Notion access is scoped by Notion's own page picker (pages shared with the integration) plus admin-selected repositories; OpenReview stores a nominal one-year expiry because Notion does not report token lifetimes, and relies on refresh-on-401.

- 2026-10-14 — Billing seats = owners + admins + members (viewers free); quota = seats × reviews per seat per UTC calendar month, counted at enqueue in a per-period counter table (no review scans).
- 2026-10-14 — A review blocked by billing is stored as a `failed` review with a `Billing:` error (not a new status), so existing lifecycle, retry-on-new-request and UI paths handle it unchanged.
- 2026-10-14 — Stripe is called with a tiny fetch client instead of the stripe SDK (only four endpoints are needed; keeps the Convex bundle small); live keys are refused unless BILLING_ALLOW_LIVE=true.

- 2026-10-14 — SSO/SAML deferred: a self-hostable OIDC/SAML broker in front of OpenReview can be added later as one more OIDC provider using the same identity/linking rules; no tenant has requested it and it needs per-tenant IdP configuration UI.
- 2026-10-14 — Account linking only via verified email on both sides (GitHub contributes no email; self-managed GitLab emails are untrusted); explicit linking while signed in covers everything else.
- 2026-10-14 — Email invitations are bearer links (single use, 7 days, revocable) accepted by whichever account signs in, because GitHub sign-ins carry no verified email to compare; the invitee's address only receives the link.
- 2026-10-14 — Removal from a workspace signs the member out everywhere (sessions are per user, not per workspace) and revokes that workspace's API keys and bridges.

- 2026-10-14 — Public docs use Markdown (an MDX subset) rendered at build time with the existing react-markdown/remark-gfm stack instead of adding @next/mdx — no new dependency, and the same files stay readable on any Git host; MDX components were not needed.
- 2026-10-14 — The landing page's pricing section renders only when BILLING_ENABLED=true; the price label is operator-configured (BILLING_SEAT_PRICE_LABEL) so the page never invents prices.

- 2026-10-14 — E4 component system: a small in-repo kit (app/ui) over the existing CSS tokens instead of Tailwind + shadcn/ui — Tailwind's preflight would restyle the hand-written CSS everywhere and both need new packages; the kit gives typed primitives that new UI adopts incrementally.

- 2026-10-14 — Analytics rollups are recomputed from raw rows per org-day (hourly for the last 2 days, daily for the last 35) instead of incremented by event hooks, so every path that changes a finding's status is reflected without instrumenting each one; dashboards never scan raw tables. Time saved counts addressed findings only (not every finding), to avoid overstating. Charts are in-repo SVG (no chart dependency).

- 2026-10-14 — Azure DevOps diffs are computed locally (Myers, 3-line context, edit bound 4,000 → whole-file fallback) because the iteration-changes API returns object IDs only; the summary thread is created closed so it never blocks comment-resolution branch policies; PR statuses (not commit statuses) carry the outcome because Azure check-like UI is per pull request.

- 2026-10-14 — "Open in agent" links are limited to the three officially documented prompt deep links (verified in Cursor, Claude Code and OpenAI docs on 2026-10-14); Codex documents no prompt length limit, so OpenReview caps it at 8,000 characters and offers copy beyond that. No other schemes are invented.
