# Evidence-backed Fix explanations

October 4, 2026. The prior review-detail UI withheld unsupported historical execution claims, but the bridge constructed agent prompts from the original stored finding, and the Findings list/portable task still exposed those claims. A native pre-update inspection of GitHub acceptance PR #4's portable task showed “failed tests” and “producing test failures” without recorded execution evidence.

`fixPrompt` now checks title, description, impact and expected remediation with the shared execution explanation guard. Runtime evidence must match each finding's exact revision; absent, wrong-revision, unstarted or contradictory evidence cannot support the narrated outcome. A multi-revision task cannot borrow one finding's runtime result for another finding. The prompt separates exact quoted source from recorded execution status and command. Raw runtime output is excluded. Predicted behavior and source assertions remain permitted. This uses the existing lexical safeguard; it does not claim semantic detection of every possible paraphrase.

Bridge creation supplies the saved review evidence. Review-detail Copy Fix All supplies that evidence too. Findings-page copied tasks have no bundled runtime receipt and conservatively make no execution claim. Finding `get`/`list` now apply the same exact parent/finding revision check to all narrative fields, including expected remediation; review-detail remediation now uses the guard as well. Original stored findings remain intact for diagnostics. Feedback/lifecycle/source-reader authorization and launch semantics are unchanged.

Three Node regressions cover unrecorded claims in every narrative field, quoted-source preservation, exact outcome/revision, unstarted execution, no raw runtime log and mixed revisions. The backend regression creates and atomically claims real fixture requests with absent/wrong-revision/unstarted/matching evidence, inspects both finding API read paths, verifies no-commit/push instructions, and confirms the stored original explanation is unchanged. These are controlled regressions, not a new live runtime job or agent execution.
