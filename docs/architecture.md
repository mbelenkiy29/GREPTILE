# Architecture and trust boundaries

`src/engine/review.ts` is the shared review engine. GitHub and CLI construct `ReviewInput`; adapters do not duplicate reasoning logic. Indexing parses TypeScript/JavaScript ASTs with the installed compiler and extracts basic declarations/imports in other languages. Graph lookup combines imports, reverse imports, exact symbols, tests, configuration files, and full-text source chunks. Relative module edges include re-exports, literal CommonJS/dynamic imports and available TypeScript sources behind emitted JavaScript paths. SHA/version-bound relative module receipts are re-resolved against each job inventory, so new/deleted targets refresh only affected importers. Receipts load from a separate table for the current bounded batch. Stored graph versions trigger a one-time reparse on the next index job; independent embedding caches and unchanged-source knowledge filters remain intact. Optional 1,536-dimensional embeddings add repository-scoped semantic matches. Retrieval ranks and deduplicates source snippets under character-based estimated token budgets.

The review pipeline runs correctness, security, data, compatibility, testing, performance, and applicable rules specialists with bounded concurrency. Model candidates must pass response validation, severity/confidence filtering, changed-line checks, exact evidence matching, deduplication, and an independent verifier. Resolution is explicitly judged, not inferred from absence of new comments. Summaries are generated from verified findings and source context.

Convex HTTP handlers authenticate exact webhook bytes before storing payload blobs. A transaction claims delivery IDs and schedules processing. GitHub App installation identity is bound to a workspace by a signed, expiring setup callback. Installation tokens live only in action memory. Review records claim repository/PR/head identity and cancel obsolete queued/running work. Stored results make publishing retries avoid repeated inference.

Browser authentication uses GitHub App OAuth, encrypted short-lived setup credentials, and signed session tokens. Convex independently verifies tokens and membership on every public user function. The service secret permits only server identity/bootstrap operations. API key owner membership and workspace scope are checked separately. Do not expose the Convex admin key or service secret to a browser or coding-agent client.

Repository code, PR descriptions, comments, learned preferences, and model output are untrusted. System prompts separate them from instructions; model text cannot execute tools, change permissions, or control API destinations. Output validation and evidence checks reduce hallucinations but are not a proof of model accuracy. No repository tests or package install scripts run on the application host.

Known limits during implementation: Graph extraction outside TS/JS is heuristic. Context is estimated at four characters/token. Truncated GitHub recursive trees fall back to a bounded per-subtree walk (3,000 subtree requests, 1,000,000 files). API/dashboard listings are bounded, and overview metrics describe their window. Review inference uses a tenant-scoped 24-hour persistent cache plus a bounded process cache. Further coverage/performance work is tracked in `docs/implementation-status.md`.

Scale and degradation: review and index steps read only the indexed files they need (`repositories.filesByPath` in batches of 200, `filePage` pages of 1,000, `filesUnder` prefix ranges); `repositories.data` returns configuration, rules and preferences only. Index completion sweeps stale files in batches before `finishIndex`, which no longer receives the full path list. Oversized pull requests are risk-ranked (`riskScore` in `src/engine/classify.ts`): fast/standard/deep review at most 200/350/500 changed files and drop the lowest-risk patches to fit the 300 KB context budget. GitHub-omitted diffs and files beyond its 3,000-file listing are reported as skipped instead of failing. Every skipped file appears with its reason in the summary's Coverage section and in the dashboard's review diagnostics. Specialists run with `Promise.allSettled`: failures are recorded per category with a visible coverage note, and the review fails only when every specialist fails.

Index exclusion accounting uses `indexSkippedFiles.by_job_path` receipts for content-time exclusions. The first 500 details remain the inspection sample; indexed receipts deduplicate files beyond that bound across retried batches, atomically with the job count and behind existing index authority/lease checks. Receipts are per job and contain no source or credentials. See [index skip recovery](internal/index-skip-recovery-acceptance.md) for migration and evidence limits.
