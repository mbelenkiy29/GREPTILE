## Implemented

- Next.js application with GitHub OAuth, workspace onboarding/switching, installation setup, repository selection, and four primary portal tabs with secondary navigation. Repository settings, custom rules, feedback, roles, invitations, preferences, API keys, and cancellation persist in Convex.
- GitHub App JWT/short-lived installation tokens, permission checks, repository enumeration, exact-byte webhook HMAC authentication, persisted payloads/delivery IDs, installation/repository lifecycle handling, PR triggers, review comments, collaborator-authorized commands, and follow-up conversations.
- Durable repository indexing in 20-file batches. Source blobs, symbols, graph edges, full-text chunks, metadata, progress, and optional semantic vectors persist. Unchanged blob SHAs are reused, changed/deleted sources replace/prune their context, and pushes during indexing schedule a fresh pass.
- Shared TypeScript engine: change classification, graph/text/optional vector retrieval, bounded parallel specialists, exact source evidence, changed-line validation, confidence/severity filtering, deduplication, independent verification, summaries, and explicit resolution assessment.
- PR/head claims cancel obsolete reviews. Publishing uses persisted results and GitHub markers. Follow-up publishing reuses saved answers. Reviews, indexing, webhooks, conversations, and knowledge generation have bounded retries/recovery with visible failures.
- Automatic knowledge generation with linked past findings, repository-wide historical review context, interpretable positive/negative feedback preferences, Fast/Standard/Deep context budgets, model routing, usage/cost records, and tenant-scoped 24-hour review inference cache.
- Native Anthropic Messages and OpenAI-compatible OpenAI/OpenRouter/custom provider adapters. Optional compatible embeddings use a fixed 1,536-dimensional Convex vector index.
- `openreview review --agent`, JSON/text/security modes, local committed Git indexing, login/status, portable fix prompts, authenticated HTTP API, and eight MCP tools using the same persisted context.
- Non-root standalone Docker web image, pinned backend image, Compose, secure local bootstrap, deployment/architecture/schema/security/contribution documentation, and a ten-fixture real-model evaluation harness.
- Local `pnpm demo` runs real inference on existing PR fixtures and produces findings/evidence/context/usage/fix prompts without GitHub.
- Operator-run optional runtime container helper with digest-pinned images, no network, no application secrets/host mounts, read-only root, bounded tmpfs/CPU/memory/PIDs/time/output. It captures commit-bound JSON evidence that can be attached through the CLI/API, reaches specialists, and appears in review details. Execution remains explicitly operator initiated.

## Known ceilings

- TS/JS uses compiler ASTs; other language declaration/relationship extraction is heuristic rather than compiler-grade. Graph edges and full-text/vector retrieval improve context but do not guarantee complete static analysis.
- Context budgets estimate four characters per token. Individual source files are limited to 200 KB; selected review context is bounded. PRs over 500 changed files or 300 KB of patch fail explicitly. Truncated GitHub trees/text patches fail rather than silently claiming full coverage.
- Local CLI reviews committed HEAD against a merge base, with up to 5,000 eligible files / 20 MB. It does not review unstaged edits or execute repository code.
- Full-text search is repository scoped. Optional vectors summarize the first 8,000 characters of each file. Generated knowledge is bounded to 30 selected files / 40,000 characters / eight entries per update.
- Analytics reads the complete selected period (at most 366 days) using time indexes and applies repository, team, and author filters. Large periods can exceed Convex read limits; daily aggregates are the upgrade path. Findings and pull requests have pagination. Repository listing and some graph/agent lookups have documented bounded windows. Knowledge recovery scans up to 1,000 repositories per sweep; add a status index when that ceiling matters.
- Specialist concurrency is two per review. There is rate limiting and transactional review/index claims, but no global provider-wide concurrency pool across workspaces.
- Cancellation checks between stages; an in-flight HTTP model request may finish. A terminal failure is retained for operator inspection/retry rather than retried indefinitely.
- Feedback updates inspectable preferences; there is no uncontrolled training. Pattern redaction is defensive and cannot guarantee every secret is removed.
- Branch browsing is a bounded snapshot of up to 200 branch heads with an explicit truncation indicator. Reviews always use exact PR head SHAs.
- Historical retrieval considers the latest 100 repository findings and passes up to 20 relevant findings; knowledge links the latest 100.
- Failed provider/schema calls may have unreported billable tokens; their error records use zero as unavailable usage, not a free-inference claim.
- Evaluation scoring uses keywords/locations and requires human adjudication. Transport/orchestration tests establish behavior, not model accuracy.
- Automatic runtime validation is opt-in and requires a separately running paired worker with prebuilt/offline dependencies. Exact-revision archive acquisition currently supports GitHub Cloud; unsupported providers fail visibly. A persistent local worker failure/report/resumed-review flow passed; successful jobs and hosted worker acceptance remain outstanding.
