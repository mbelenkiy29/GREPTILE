## Enforcement

Before every hosted model HTTP attempt, `HttpModel` reserves its full maximum output plus a conservative input ceiling based on the UTF-8 request JSON and 1,024 framing tokens. Validation corrections are included in each subsequent attempt's serialized request. Reservations are atomic Convex mutations against one durable ledger shared by all workspaces. This applies to normal/P4 reviews, knowledge generation and normal/P4 conversations; both source-indexing and retrieval embeddings use the same gate. Inner model retries and outer worker retries all re-enter reservation before transmitting, so their multiplicative retry count cannot bypass available capacity. Existing caches return before reservation because no provider request occurs.

Reported nonnegative integer token receipts can settle a reservation once, at its recorded verified price, releasing the unused portion. Replayed identical receipts do nothing; changed, malformed or oversized receipts reject and retain the reservation. Missing receipts, transport failures, crashes or billing-storage failures retain their whole maximum reservation. No timeout sweep releases ambiguous paid requests. A billing receipt failure after successful generation does not repeat the paid request. Budget refusal terminates the current generation while preserving accumulated usage for the worker's failure accounting. An outer retry can run, but it cannot send without another approved reservation.

Prices are independently verified from official standard-price model references: [GPT-4.1](https://developers.openai.com/api/docs/models/gpt-4.1) ($2 input/$8 output per million) and [text-embedding-3-small](https://developers.openai.com/api/docs/models/text-embedding-3-small) ($0.02 input per million). Only OpenAI's exact HTTPS v1 endpoint and those model names (including the GPT-4.1 snapshot) are currently priced. Unknown providers, custom endpoints or other models fail closed when a budget exists; configured estimated-cost fields cannot override these prices. Cached input is conservatively charged at the full input rate. Price changes require operator verification and code updates before inference; this is not a provider-side billing limit.

## Operator setup and limitations

A self-hosted deployment without a budget record preserves its existing behavior. Operators initialize through the internal `inferenceBudget:initialize` mutation with integer USD micro-units, an already-accounted historical floor and an evidence description. `inferenceBudget:status` exposes internal accounting. Initialization is idempotent for identical values and cannot reset or increase an existing limit. These are internal functions, not customer API permissions; no new key/access grant was created.

This ledger gates the hosted execution paths. Standalone CLI/evaluation processes and external coding-agent accounts do not use this Convex hook and are **not** controlled by it; no such paid run is authorized without separate reconciliation/enforcement. Other clients sharing the provider key, provider reporting lag, vendor price changes and unsupported providers cannot be covered by an application ledger alone. The historical margin and refusal on unknown prices are conservative controls, not universal billing guarantees. Current full provider/OS/Fix/approval acceptance remains incomplete.
